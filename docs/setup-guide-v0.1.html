Chapitre 01 — Quick StartOpowAI v0.1
Quick Start

Démarrer en
deux commandes.

C'est tout ce qu'il y a à faire dans le terminal. Le reste, Claude le fait pour toi.

  1. Cloner OpowAI et installer

    Ouvre un terminal et colle ces deux lignes :

    git clone https://github.com/Flow8w/OpowAI.git ~/opowai
cd ~/opowai && bash install.sh

    Le script install.sh détecte tes prérequis, crée un virtualenv Python, installe les dépendances, configure les permissions. Aucune intervention de ta part pendant l'install.

  2. Lancer Claude Code et démarrer le setup

    Toujours dans le dossier ~/opowai :

    claude
# Une fois dans Claude Code, tape :
/setup-opowai

    Claude prend le relais. Il vérifie ton environnement, te pose 2-3 questions de priorisation, t'accompagne pour connecter tes outils (Pipedrive, Notion, Gmail…), scanne ton contexte en arrière-plan et active progressivement les skills.

Prérequis (vérifiés automatiquement par install.sh)

Python 3.11+ · Git · Claude Code CLI (depuis claude.com/code) · Abonnement Claude Max 5x minimum (Pro à 20 €/mois sature en 30 min de setup).

Repo privé Tu dois être ajouté comme collaborateur sur Flow8w/OpowAI pour cloner. Si git clone échoue : demande l'accès à Florian, puis configure ton PAT GitHub.

Chapitre 04 — Mises à jourOpowAI v0.1
Mises à jour

Pousser & tirer
depuis GitHub.

OpowAI vit sur GitHub. Tes modifications sont sauvegardées en continu, et les nouvelles versions du système te parviennent en une commande.

Tes modifications — auto-sync transparent

À chaque action significative dans ton vault, un hook commit + push automatiquement. Tu ne touches jamais à git. Mais si tu veux vérifier : 

cd ~/opowai
git log --oneline -10      # 10 derniers commits
git status                 # état actuel

Récupérer les nouvelles versions (v0.2, v0.3…)

Quand une nouvelle version d'OpowAI est publiée, demande à Claude : 

/opowai-update

Il fait le git fetch upstream, regarde les nouveautés, te résume ce qui change (nouveaux skills, nouveaux playbooks, fixes), te demande confirmation, puis merge. Tes données personnelles ne sont jamais touchées.

Ce qui est partagé vs ce qui reste privé

Partagé (vient de l'upstream) : structure de dossiers, code Python, SKILL.md, playbooks anonymisés.
Privé (toi seul) : meeting notes, person pages, projets, OKRs, profil, état du setup. Tout ça est dans ton repo privé, et explicitement gitignored vis-à-vis de l'upstream.

Travailler depuis plusieurs machines

Tu peux cloner ton repo privé sur n'importe quel device. Au lancement de Claude Code, git pull automatique → tu retrouves exactement où tu en étais.

Aucune migration manuelle. Le repo est le système.
Chapitre 05 — DépannageOpowAI v0.1
Dépannage

Quand ça coince.

Les 6 cas qu'on a vus en bêta, et comment les régler en moins d'une minute.

« Je sature en tokens »

Tu es probablement sur Pro (20 €/mois). Passe sur Max 5x (100 €/mois). Si tu satures Max 5x aussi, monte à Max 20x.

« install.sh échoue »

Vérifie d'abord que tu as Python 3.11+ et Git. Si oui, regarde le message d'erreur. Le script install.sh est verbeux par design — il te dit où ça coince. Si Python est trop ancien, mets-le à jour depuis python.org.

« /setup-opowai ne reprend pas où je l'avais laissé »

Tape /setup-opowai --resume. Si ça ne marche pas, regarde System/.setup-state.json — s'il existe, le state est récupérable.

« Un skill devrait être activé mais ne l'est pas »

Tape /opowai-status. Le skill apparaît en ⏳ pending ? Il manque un outil — la colonne "attend" te dit lequel. Connecte-le via /setup-opowai --redo [thematic].

« Un agent récurrent ne se déclenche pas »

Demande à Claude : "Vérifie mes agents OpowAI programmés". Il regardera crontab -l et te dira si le cron est bien installé. Sinon, il te propose ./bin/opowai install-cron.

« Comment je donne du feedback ? »

Écris à florian.guerrier@gmail.com ou ouvre une issue GitHub sur le repo upstream. Les retours alimentent la v0.2.

Reset complet

Tu peux toujours faire un git reset --hard origin/main pour revenir à la dernière version stable, ou supprimer le dossier et recloner. Tes données réelles (vault) sont dans le repo — pas dans le code.
